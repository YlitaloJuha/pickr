# Pickr.

**An app that groups near-duplicate photos taken seconds apart into moments, so you tap the keepers and the rest go to Recently Deleted.** One adaptive layout for iPhone, the iPhone Duo and iPad. 100% on-device: no network, no AI, no accounts, no tracking. The name is always written with its period, even mid-sentence: "Pickr.". Version 2.0 is a ground-up rebuild for iOS 27 of the shipped 1.0; users upgrade over it, so everything it stored still has to read correctly.

Repo: https://github.com/YlitaloJuha/pickr (public, MIT). GitHub Pages serves `README.md` (the App Store **Support URL**) and `privacy.md` (the App Store **Privacy Policy URL**, `/pickr/privacy`) from `main` at `/`. Both paths must never move, `_config.yml` keeps everything else off the site, and there must be no `.nojekyll`.

**Read `docs/ARCHITECTURE.md` first** (layers, contracts, concurrency, the PhotoKit pipeline, interface rules) and `docs/PERSISTENCE.md` before touching anything stored. `docs/CONTRIBUTING.md` holds the contributor rules, `docs/SECURITY.md` the security model, `docs/RELEASING.md` the release steps. Keep the docs in step with the code in the same change.

# Commands

- `scripts/bootstrap.sh` — once per checkout: creates the git-ignored `Config/Signing.local.xcconfig` from the `.example` (team line commented out, so simulator builds work; set `DEVELOPMENT_TEAM` there for a device) and runs `xcodegen generate`. `Pickr.xcodeproj` is generated and git-ignored: change `project.yml`, never the project.
- `cd PickrKit && swift test` — the package tests (Swift Testing): `PickrCoreTests`, `PickrPersistenceTests`, `PickrModelsTests`. Runs on the Mac with no simulator. Must pass with zero warnings.
- `xcodegen generate && xcodebuild build -project Pickr.xcodeproj -scheme Pickr -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO` — the unsigned app build CI runs. Needs no simulator runtime.
- `scripts/verify.sh kit|app|app-tests|policy|all` — the same checks with per-agent DerivedData and SwiftPM paths and a lock around `xcodegen` (shared scratch `$TMPDIR/pickr-verify`, or `PICKR_SCRATCH`). `app` also checks that the bundle ID resolves to `com.juha.Culler` and that the generated project has no `DEVELOPMENT_TEAM`. `PICKR_STRICT=1` fails on any compiler warning.
- `scripts/policy-check.sh` — the privacy and code-rule greps CI runs: network and ML APIs, Photos imports, PhotoKit writes and the single `deleteAssets` call, private API (KVC, selectors, `"fileSize"`), team IDs, `print`, banned materials and glass, UserDefaults key strings and the 18 v1 keys, Liquid and `.nojekyll`, Info.plist and entitlements, iCloud storage, required-reason APIs, `#available`, dependencies, layout by space, every delete through `Curator`, the banned words in the String Catalog (21), demo mode Debug-only (22–22c) and no system UI in UI tests (23). Run it before every commit.
- `swift scripts/make-test-photos.swift [dir]` — regenerates the 40 synthetic photos (illustrated scenes, `makeScene`: one per moment, each photo a slightly shifted burst frame); `--check test-photos` checks names, sizes and EXIF capture times against the fixture timeline. Keep the committed originals.
- **Demo mode** (Debug only): launch with `-PickrDemo YES` (`-PickrDemoAppearance light|dark` forces the scheme) for the 40 test photos bundled in Debug builds, no PhotoKit, settings in memory and Kept in a fresh temporary folder. `scripts/demo-gifs.sh` records the README GIFs and screenshots from it on a USB iPhone (`--check` first; `--recorder manual` when screen capture fails); `swift scripts/frame-screens.swift` puts `images/screens/*.png` into iPhone frames. `scripts/sim-capture.sh` does the same in the iOS Simulator (hero animation `images/demo/hero*.webp` and the screenshots, framed), with no device. Steps in `docs/RELEASING.md` (README demos).
- `xcrun simctl privacy booted grant photos com.juha.Culler` and `xcrun simctl addmedia booted test-photos/*.jpg` — set up a booted simulator for the live `PickrAppTests` suite (40 records; 7 moments at the default 1-minute window). `PickrAppTests` and `PickrUITests` need an installed iOS 27.2 simulator runtime (`xcodebuild -downloadPlatform iOS`); without one, `scripts/verify.sh app-tests` still compiles them. Layout checks run on `iPad Pro 13-inch (M5)`, `iPad Pro 11-inch (M5)`, `iPad mini (A20 Pro)`, `iPhone Duo` (closed, half-open, open) and `iPhone 17 Pro`, in both orientations and with a resized window.
- CI (`.github/workflows/ci.yml`): `policy`, `secrets` (gitleaks over the pushed or PR commits; the whole history weekly), `kit` (`swift test`), `app` (unsigned build, allowed to fail) and `sim` (`PickrAppTests` and `PickrUITests` on iPhone 17, iPad Pro 11-inch (M5) and iPhone Duo, advisory; a failed test is retried once and a test is stopped after 5 min, because the hosted simulators, the iPad's especially, are sometimes slow to launch or answer). The macOS jobs need Xcode 27.2, which is on GitHub's `xcode-27` runner image, not `macos-26`.

# Map

- `PickrKit/Sources/PickrCore/` — Foundation only, pure `Sendable` values. `Contracts/` (`PhotoID`, `AssetRecord`, `Moment`, `Grouping`, `Library`) holds the shared types and `PhotoLibraryClient`; next to it `Clusterer`, `MomentPipeline`, `Savings`, `Selection`, `IndexMath`, `DensityHistogram`, `PickrFormat`, and `GroupingLogic` (`TimeWindow`/`ScanRange` statics).
- `PickrKit/Sources/PickrPersistence/` — `KeyValueStore` (UserDefaults or in-memory), `PersistedKeys` (every UserDefaults key string, nowhere else), `SettingsRepository`, `StatsRepository`, `KeptStore` (actor, `kept.json`, `KeptStoreError`), `FileStore`, `MigrationV1` (`isUpgrade`, `run`, `legacyKeptIDs`), `LegacyTips`.
- `PickrKit/Sources/PickrModels/` — MainActor `@Observable` state, no SwiftUI: `AppServices` (composition root, `launch()` order), `LibraryModel`, `SettingsModel`, `KeptModel`, `Curator` (the only path for deletes, Kept and stats), `ReviewSession`, `ToastCenter`, `ToastMessages` (every toast text), `Router`.
- `PickrKit/Sources/PickrTestSupport/` — `FakePhotoLibrary`, `Fixtures` (the test-photos timeline). Tests: `PickrKit/Tests/` (`PickrModelsTests/Support/Harness.swift`, `PickrPersistenceTests/Support/V1Fixture.swift`: every v1 key with its exact type). Key spelling is pinned by `PersistedKeysTests` and policy check 9d.
- `Pickr/App/` — `PickrApp`, `LiveServices`, `PickrCommands` (keyboard menu commands, `CommandHaptics`); `Demo/` (`DemoMode`, `DemoPhotoLibrary`, `DemoImageLoader`; every file `#if DEBUG`). `Pickr/Platform/Photos/` — the only code that imports Photos/PhotosUI: `LivePhotoLibrary`, `LibraryIndexer` (actor), `IndexCache`, `LibraryChangeObserver`, `AssetSizer`, `Deleter`, `AssetQueries` (every fetch and its flags), `PhotoErrorMapping`, `ImageLoader`, `LimitedLibraryPicker`, `PhotosLog`, `CloudIdentifiers` (Kept portability, P2).
- `Pickr/DesignSystem/` — cards, tiles, grid, `ToastHost`, `Feedback`, `ImageLoading`, `ColumnLayout` (stack or split), `AmbientColor` (`.ambientBackground(_:strip:)`, `AmbientSource`, the backdrop cache), `AmbientPalette` (the colour maths), `AmbientStripLayout` (the list strip's geometry), `ScrollFocus` and `FocusLine` (which row or tile is most visible), `Theme` (with `Motion`), `DragSelect` (range-painting in the Review grid), `PhotoPager/` (UIKit: `PhotoPager`, `PhotoPagerController`, `PagerCell`, `ZoomingImageView`). `Pickr/Features/` — `Root`, `Moments` (with `MomentsColumns`, `ReviewStartView`), `Review`, `Kept` (with `KeptColumns`), `Grouping`, `Settings`, `Tips`.
- `PickrAppTests/` (hosted: index cache, error mapping, image loader, ambient focus, strip and palette, demo mode, the live suite), `PickrUITests/` (`PickrUITests`; `DemoRecordingTests`, skipped unless `PICKR_DEMO=1`).
- `scripts/` — `bootstrap.sh`, `verify.sh`, `policy-check.sh`, `make-test-photos.swift`, `demo-gifs.sh` (with `enable-ios-screen-capture.swift`), `sim-capture.sh`, `frame-screens.swift`. `NOTICE` — what the MIT licence doesn't cover (name, icon, screenshots, `images/` artwork), Apple trademarks, the synthetic photos, no dependencies.
- `Config/Shared.xcconfig` — `PICKR_BUNDLE_ID = com.juha.Culler`, empty `DEVELOPMENT_TEAM`, includes the local signing file. `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` live in `project.yml`.

# Rules

These hold for every change; `scripts/policy-check.sh` enforces most of them.

- **Identity never changes:** bundle ID `com.juha.Culler` (set only as `PICKR_BUNDLE_ID` in `Config/Shared.xcconfig`), display name `Pickr.`, no entitlements or capabilities. Target, module and scheme are `Pickr`.
- **Devices:** iPhone, iPhone Duo and iPad (`TARGETED_DEVICE_FAMILY` "1,2"); iPhone in portrait and both landscapes, iPad in all four orientations; **one scene** (`UIApplicationSupportsMultipleScenes` = NO, because `AppServices` and the `Router` are app-wide); no `UIRequiresFullScreen`; the window resizes freely (Stage Manager, Split View). iPad support is **permanent** for the App Store record once a build with it is live, so 2.0 ships with iPad only if the simulator checks pass on all three iPad sizes. Until then, user-facing text (README, App Store copy, `privacy.md`, in-app strings) never claims iPad and says "your device", not "your iPhone".
- **Layout by space, never by device:** decide with `horizontalSizeClass` (write `== .regular`, never `!= .compact`), `verticalSizeClass` and the view's own width (`onGeometryChange`), measured by the container that switches. Never the device model, `userInterfaceIdiom`, `UIScreen.main`, `UIDevice.current`, the interface orientation, `UIApplication.shared.windows`/`keyWindow`, posture or the hinge APIs (27.1; unused). Pixel sizes come from `displayScale` (`traitCollection.displayScale` in the pager). `ignoresSafeArea` always names its edges and never the horizontal ones on content. Models never hold layout. Every resize is live: only image re-requests wait for `isInteractivelyResizing` to end. Start a commit with `Task { await session.commit() }`, never inside a `.task` modifier, which a container swap cancels.
- **No team ID in any tracked file.** It lives only in the git-ignored `Config/Signing.local.xcconfig`. No `bundleIdPrefix`, `DEVELOPMENT_TEAM` or `PRODUCT_BUNDLE_IDENTIFIER` in `project.yml`. Never pick a team in Xcode's Signing UI. Never commit `.p8`/`.p12`/profiles/`ExportOptions.plist`.
- **No network, no iCloud storage:** no `URLSession`, `URLRequest`, `Network`/`NWConnection`, `WKWebView`, CloudKit, `NSUbiquitousKeyValueStore`, analytics, crash reporting, ads, third-party SDKs or dependencies. `Link`s open other apps. iOS may download iCloud originals for display; `privacy.md` says so.
- **No AI or ML:** no Vision, Core ML or Foundation Models. Grouping uses capture time; protection uses favorite and rating.
- **One deletion site:** `PHAssetChangeRequest.deleteAssets` only in `Pickr/Platform/Photos/Deleter.swift`, inside `performChanges` (iOS dialog, Recently Deleted for 30 days), reached only through `Curator` → `PhotoLibraryClient.delete`. Keep the rails: protected favorites, re-fetch at delete time (hidden excluded), the extra dialog at ≥ 20 photos, silent cancel, an error toast on every failure, stats from the receipt only.
- **Photos imports** only in `Pickr/Platform/Photos/`; PhotoKit change requests (`performChanges`, `PHAssetChangeRequest`, …) only in `Deleter.swift`. Never `PHImageManagerMaximumSize`, never KVC or selector lookups (no private `"fileSize"`; sizes come from `PHAssetResource.dataSize`).
- **Persisted keys are frozen:** never rename, retype or reinterpret a UserDefaults key; strings only in `PersistedKeys.swift`; `ignoreList.photoIDs` is read only through `MigrationV1.legacyKeptIDs(in:)` and never written or removed in 2.x; an absent `settings.hapticFeedbackEnabled` means `true`; read with `object(forKey:)` and a cast; defaults stay absent (`save` writes only values that would read back differently). `MigrationV1.isUpgrade` requires `app.schemaVersion < 2` and is evaluated before anything writes `stats.firstUseDate`, so fresh installs never see What's New. A new key gets a row in `docs/PERSISTENCE.md` in the same change.
- **Stored files:** `kept.json` is never overwritten when it can't be read safely (a newer version, or before first unlock); an unreadable one is renamed `kept.unreadable-<UUID>.json`. The index cache (`Library/Caches/Pickr/index.v1.plist`) is disposable, never reused across access levels, and deleted when indexing starts with access denied.
- **Privacy manifest:** `PrivacyInfo.xcprivacy` declares UserDefaults `CA92.1` only. Using a required-reason API (file timestamps, disk space, system boot time, keyboards, App Group defaults) means updating the manifest in the same change, and `privacy.md` (with a new "Last updated" date) if what's stored or read changes. The App Store label stays "Data Not Collected".
- **Logging:** `os.Logger(subsystem: "com.juha.Culler", …)`, errors only, photo identifiers `privacy: .private` (error domains and codes may be public). No `print`. Signposts stay local; no telemetry.
- **Toasts come from the models** (`Curator`, `ReviewSession`, `Router`), never from views; views add haptics only, and commit results play through `CommandHaptics` at the root (the screen that started a commit may be gone when it ends). `ToastCenter` is the only toast timer (5 s, 10 s with VoiceOver). `toastHost(isRaised:)` (raised from model state while Review or the Kept moment is on top) keeps the capsule above whatever that screen marks with `toastsStayAbove(_:)`: its bottom bar, and in One by One the filmstrip. New toast texts go in `ToastMessages.swift` and are added to `Localizable.xcstrings` by hand (the package has no resources).
- **Main-actor cost:** `KeptModel.groups(index:window:)` and `liveIDs(in:)` are O(library): compute them in `.task(id:)` or cache them, never in `body`.
- **Viewer images:** a viewer stream carries only the high-quality image; an empty stream means the load failed, and `PagerCell` keeps its own tile image and shows the note. Never add a placeholder to `images(for:size:)`.
- **Liquid Glass, system first:** explicit `glassEffect` only in `DesignSystem/ToastHost.swift`, `Features/Review/Filmstrip.swift`, `Features/Review/KeepToggle.swift`. No UIKit glass (`UIGlassEffect`). Banned in `Pickr/`: `presentationBackground`, `toolbarBackground`, every `…Material`, `UIBlurEffect`/`UIVisualEffectView`, `safeAreaInset` (use `safeAreaBar`). One `.glassProminent` action per screen; inline buttons are bordered. Never glass on cards, tiles, photos or rows. The toolbar item holding the `.tabs` All / One by One picker gets `.sharedBackgroundVisibility(.hidden)` (the picker brings its own glass). Split views, sidebars, popovers and form sheets get system glass on their own. `ReviewStartView`'s button is inline (`.borderedProminent`); hover highlights and the keyboard focus ring are solid content, never glass.
- **Ambient backgrounds** (`DesignSystem/AmbientColor.swift`, `.ambientBackground(_:strip:)`): blurred photos behind the content so the glass picks up their colours. `AmbientSource` is `.plain` or `.photo(PhotoID)`; there are no colour washes. **Lists** (Moments and Kept in the stack) draw a continuous strip (`AmbientStripLayout`, pure): each moment's first photo sits 1:1 behind its row and scrolls with it, photo *i* opaque at row *i*'s centre and blending linearly into *i + 1* by the next centre, in painter's order, visible rows ±1 only; a row whose photo arrives late shows its nearest neighbour's (no per-row fade). **Grids, One by One and the Kept photo** show one photo (the focused tile, or the photo shown) that cross-fades over the old one in 0.6 s, layered, never through the plain background; a new one waits for a running fade and only the latest follows. **Focus:** the row or tile whose frame crosses a line 40 % down the scroll container wins, else the nearest; in a grid row, the tile nearest the centre (`FocusLine`). `ScrollFocus<ID>` measures in window (`.global`) coordinates with `onGeometryChange` (`.scrollFocusContainer`, `.scrollFocusItem`, `.onScrollFocusChange`); `scrollFocusItem` is never conditional (one view type, so a row keeps its identity), and list row traits (`.cardRow()`, `listRowBackground`, …) go on the row's **outermost** view. `focused` and `frames` are observable: read them only in the background modifier, never in the list's body. Plain-list section footers draw an opaque band over the strip: use clear rows instead (`KeptScreen`). **Split:** the detail column paints the tab's one source (the start views: the sidebar's focused moment); the sidebar paints nothing (it still tracks its focus). **Images:** 64 px backdrops plus the 8×8 average colour, drawn off the main actor from thumbnails already shown (`ThumbnailView` reports them), with the blur baked in once by Core Image (`AmbientPalette.backdropBlurRadius`, about 60 pt on screen), then only scaled to fill; 300 newest in memory, nothing persisted; a single photo missing after 200 ms is requested at `.card`. **Never a live SwiftUI `.blur` on the background and never `backgroundExtensionEffect()`:** on iOS 27 devices both rendered the layer black. **Legibility:** saturation 0.8, then a tint (the average colour, saturation ≤ 0.45, lightness 0.88–0.96 light / 0.04–0.09 dark, 90/10 with `systemGroupedBackground`, at 42 %; per segment in the strip), then a dim (25 % white / 35 % black; once over the whole strip). Worst case about 5.6:1 for primary text (5.62 light, 5.58 dark, blends included; `AmbientPalette.swift` header). Reduce Motion → instant; Reduce Transparency or Increase Contrast → plain background and nothing loaded. A layout swap shows the current look at once and re-lays out the strip. Cards, tiles, sheets, popovers, Settings and onboarding never get one; the pager stays clear; VoiceOver ignores it.
- **Navigation:** a `TabView` with two tabs (Moments, Kept) and `.tabViewStyle(.tabBarOnly)` (no sidebar mode: with two tabs it added only a second, confusing sidebar button): a bottom tab bar when compact, a top tab bar when regular. Each tab is a column container (`MomentsColumns`, `KeptColumns`) that picks `ColumnLayout` from its own width: **split** when the horizontal size class is regular, the tab is **≥ 740 pt** wide and the list is showing; otherwise the iPhone **stack**. Split: `NavigationSplitView` (`.balanced`) with the list (300–420 pt) beside Review or the Kept moment; the list highlights the moment under review, and `ReviewStartView` ("Clean Up 7 Moments") fills an empty detail instead of the bottom accessory. Stack: Review and the Kept moment are pushed with the tab bar hidden, and it returns as soon as they start closing (`router.review` / `router.keptPath` let go, not after the zoom). The tab bar never minimizes (`.tabBarMinimizeBehavior(.never)`). The **Clean Up 7 Moments** bottom accessory shows on **both tabs** whenever the Moments tab is stacked with moments listed and nothing is pushed on either tab (`RootView.showsAccessory` checks both paths, never `router.tab`, so switching tabs never resizes the tab bar); from Kept it switches to Moments and starts there. At most one sheet at a time (Adjust = `GroupingSheet`, Settings, What's New; Settings and What's New are form-sized when regular). **Adjust is a popover** anchored to its toolbar button when the Moments tab is split, the S6 sheet otherwise; `router.sheet` stays the single source. Never a sheet from a sheet. One toast host per tab container, on the trailing column.
- **Motion:** every animation is one of `Motion` (Theme.swift: `advance`, `crossFade`, `chrome`, `listChange`, `reducedFade`; BLUEPRINT §3.6); system transitions are left alone and a layout swap never animates. Back or Esc from Review sets `Router.scrollTarget` (in `closeReview`) so the list brings the card on screen before the zoom returns to it.
- **Context-menu previews** get `.environment(\.imageLoader, …)` passed explicitly: iOS hosts them outside the view's environment.
- **Lossless swaps:** `Router` keeps `momentsPath.contains(.review) == (review != nil)`; `startReview(at:)` during a review replaces the session and carries the summary over; the last selection per moment is remembered for the app session. So a stack ↔ split swap, a rotation or a Duo fold never loses the moment, the selection, All / One by One or the photo index. The Moments list's scroll anchor lives above the stack/split switch.
- **Keyboard and pointer:** `App/PickrCommands.swift` adds a **Clean Up** menu (Space Keep Photo, ⌘⌫ Delete, ⌘K Keep All, ⌘↓ Skip, ⌘↑ Previous Moment, ⌘1 / ⌘2 All / One by One, ⌥⌘1 / ⌥⌘2 tabs, ⌘Z Undo, ⌥⌘A Adjust…, ⌘, Settings…, ⌘R Refresh), reading `@FocusedValue(\.reviewSession)` and disabled while a sheet or popover is up. `ReviewScreen` handles arrows, Return, Esc and 1–9. Tiles get a hover highlight; drag-select (`DragSelect.swift`) paints keep or unkeep across a range in the Review grid on every device, through `session.toggle(_:)`.
- **Confirmations:** deletes get only the iOS dialog, plus one app `confirmationDialog` at ≥ 20 photos ("Delete all 47 photos in this moment?"). Reversible actions (Keep All, Show Again) get an undo toast, no dialog. Never write "permanently": photos go to Recently Deleted.
- **iOS 27.0 minimum, no `#available`.** Swift 6, strict concurrency, MainActor by default in the app and `PickrModels`; `PickrCore` reads no clock (`now` and `Calendar` are passed in). No `withAnimation` in models. No fire-and-forget `Task {}` that outlives its view.
- **Copy (owner-approved plain language; overrides the blueprint's terms):** name the outcome, not the mechanism. Never "scan", "range", "restore", "select", "invert", "session", "haptics", "grouping", "cluster" or "permanently" in the UI; "Recently Deleted" stays. Words: "moment"; **Keep All** / **Delete All** ("Favorites are kept."); **Delete 4 Photos** + "Frees up 6.8 MB"; **Keep All & Next**; **Skip**; **Clean Up 7 Moments** + "Frees up to 32 MB"; "… to free up"; Kept tab sections **Moments you kept** / **Photos you picked**; **Show Again** / **Show Moment Again** / **Show Photo Again** / **Show All Again…**; **Adjust** (sheet and toolbar button): **Photos taken within** 10 sec · 30 sec · 1 min · 3 min · Other…, **Look back** Week · 2 Weeks · Month · Everything · Pick Dates… (**First day** / **Last day**); **Sort**: Newest First · Biggest First; **All** / **One by One**; **Vibration**; **Never delete favorites**; **Choose Photos**; photo-access primer **Photo access** + **Continue** (App Review 5.1.1(iv): never "Allow" on a button before the iOS prompt); **Just now** / **All time**; **Photos deleted** / **Space freed up** / **Moments done** / **Using Pickr. since**; **How Pickr. Finds Moments**; **Send Feedback**. `docs/ARCHITECTURE.md` (Words) maps each to its code name; code names don't change. Short, plain, second person, no exclamation marks; "—", "·", "…". The photo-access prompt's sentence (`NSPhotoLibraryUsageDescription` in `Info.plist`, owner decision, COPY.md) is plain too: "Pickr. looks at when your photos were taken to find near-duplicates…", never "scans" or "groups". User-facing strings are `LocalizedStringKey`/`String(localized:)` literals. Bytes in decimal units (`ByteCountFormatStyle(style: .file)`).
- **Accessibility:** every control has a label, every gesture a visible alternative and an accessibility action; Reduce Motion turns zoom transitions into cross-fades.
- **Personal photos never enter the repo,** an issue or a screenshot: use `test-photos/` or demo mode.
- **Demo mode stays harmless:** `Pickr/App/Demo/` and every mention of it are `#if DEBUG`, and Release never bundles `test-photos/` (policy 22–22b). `Deleter` refuses demo mode before `performChanges` (22c), and `LivePhotoLibrary`, `ImageLoader` and `LibraryChangeObserver` `precondition` it off. Demo UI tests check for the `pickr.demo-mode` marker before touching anything; no UI test touches SpringBoard, other apps or interruption monitors (23), and the live `PickrUITests` test stops at the Delete button.
- **`README.md` and `privacy.md` contain no Liquid template tags** (they would break the Pages build and freeze the live privacy policy). The support email in both stays as it is.

# Code style

- Logic goes in `PickrKit` with Swift Testing tests; views stay thin. Test first: a bug fix starts with a test that reproduces it.
- Contracts in `PickrCore/Contracts/` change only on purpose: update `FakePhotoLibrary`, the tests and `docs/ARCHITECTURE.md` with them.
- Minimize comments: short notes on why, and a one-line purpose for a non-obvious type. No changelog in this file.
